# 威胁模型：这个软件防什么、不防什么

写这份文档的原因很实际：**只有写清楚边界，你才不会在错误的地方投入精力，
也不会在某个以为被保护的地方被坑。**

一份说不清自己边界的密码管理器，比一个功能少但边界清楚的更危险。

---

## 一、我们防的（设计目标）

| 场景 | 防护手段 | 强度 |
|---|---|---|
| 手机丢失，捡到的人翻看相册/App | 库文件是 AES-256-GCM 密文；主密钥来自主密码的 60 万次 PBKDF2 | 强（取决于主密码强度） |
| 手机被偷，对方在锁屏界面试图打开 App | Face ID（`biometryCurrentSet`）+ 系统级 Keychain 保护 + 文件 `NSFileProtectionComplete` | 强 |
| 你复制密码时被别的 App 读取剪贴板 | 剪贴板写入带 60 秒系统过期时间 + `localOnly`（不随 Handoff 同步） | 中 |
| App 切到后台时被截图，密码显示在 App 切换器缩略图里 | 场景切换到 `inactive`/`background` 时用不透明遮罩替换内容 | 强 |
| 备份文件落到网盘/邮箱里 | 导出的是**密文本身**，导出流程里没有任何解密步骤 | 强（等价于主密码强度） |
| 攻击者拿到库文件后篡改头部（改迭代次数、换盐） | 整个文件头作为 AEAD 的 AAD 参与认证，改一个字节即解密失败 | 强 |
| 密码在某个网站泄露了，但你不知道 | 本地 SHA-1 + k-匿名范围查询 HIBP | 强（隐私设计见下） |
| 手滑导入一个错的文件，把现有库覆盖掉 | 恢复前**必须**用该备份的主密码成功解密一次才允许写入 | 强 |

### 关于泄露检测的隐私设计

只把密码 SHA-1 的**前 5 位十六进制**发给 `api.pwnedpasswords.com`，
服务端返回约 1000 条同前缀的候选，本地比对。
服务端无法反推你查的是哪个密码。

但仍要注意：**这条请求会暴露你的 IP 给 HIBP**，以及"你在用这个 App"这个事实。
所以这个功能：

- 默认**不自动运行**，只有你点"检查"才发请求；
- 保存密码时**绝不**后台悄悄检查；
- 全库检查是串行 + 每条间隔 120ms，不会把你的 IP 打成特征。

**这是本 App 唯一的网络行为。** 没有统计 SDK、没有崩溃上报、
不抓网站图标（那会实时泄露"我在用哪些网站"）、不连任何服务器。

## 二、我们不防的（明确的非目标）

### 1. 已越狱设备上的定向分析

在越狱设备上，攻击者可以 hook 我们的进程、dump 内存、
绕过 `LAContext` 的返回值。这类攻击需要**针对性投入**（要有人专门为你写工具），
不属于"手机丢了"的范畴。

### 2. 内存取证 / 冷启动攻击

Swift 的内存管理不保证 `Data` 里的字节在任何确定时刻被覆写。
我们没有 `mlock` / `explicit_bzero` 的可靠等价物作用于所有值类型。
我们能做的只是**尽早断开强引用**（上锁时清空状态），
让敏感内存尽快不可达。这挡住了"顺手翻一下"，挡不住"拆机读内存"。

### 3. 键盘记录 / 系统级恶意软件

如果攻击者能在你的设备上装键盘记录器（需要越狱或企业证书滥用），
主密码在输入那一刻就泄露了。这不是 App 层能解决的问题。

### 4. 你自己主动泄露

- 把主密码写在便利贴上贴在手机背面；
- 把主密码用在别的网站上（撞库）；
- 在骗子伪造的"登录页"里手动输入密码（钓鱼）。

**说句不客气的：这四条里任何一条发生的概率，都远高于上面那些技术攻击。**
针对钓鱼的防护是"永远用自动填充，不要手输"——自动填充不会填到
和登录框域名不符的页面上（这也是为什么我们注册了 `ASPasswordCredentialIdentity`）。

### 5. 供应链攻击

我们只用 Apple 系统框架（CryptoKit / CommonCrypto / Security），
没有第三方依赖——这是刻意的选择，因为每一个依赖都是一次信任让渡。
但 Xcode 工具链、GitHub Actions runner、以及你安装 App 的方式
（AltStore / Sideloadly）本身仍然是信任前提。

### 6. 元数据

**文件名、文件大小、修改时间、条目数量都不加密。**
`vault.pwvault` 这个文件名、以及"你有一份 47KB 的密码库"这件事
对能看到文件系统的人来说是明文。
对个人使用场景，加密元数据带来的复杂度（定长填充、隐藏文件名）
不值得。

## 三、已知的妥协（这些是刻意接受的，不是疏忽）

### 妥协 1：没有自动填充，全靠复制粘贴

**v0.2 移除了 Safari / App 内自动填充功能。** 原因很简单：
iOS 的 Credential Provider 扩展需要付费 Apple 开发者账号（$99/年）
才能拿到授权，而你不打算买。

**这件事带来的实际影响，需要如实说明：**

| 影响 | 说明 |
|---|---|
| 多两步操作 | 「密码库」里点复制 → 切到 Safari 粘贴 → 登录 |
| 剪贴板成为必经之路 | 密码会短暂进入**全局剪贴板**，60 秒后由系统级过期时间自动清空 |
| 好处：更免疫钓鱼 | 手动粘贴时，你不会往一个可疑页面上粘密码；自动填充的便利性恰恰降低了这种警惕 |

**替代方案（都试过，都不推荐）：**

- **企业证书 / 第三方签名服务**：违反 Apple 开发者协议，证书会被吊销，
  而且你要把密码库的可执行文件交给一个不受你控制的第三方签名。
  对一个密码管理器来说，这是自毁性的取舍。
- **越狱 + 插件**：越狱直接摧毁了 iOS 的沙盒和 Keychain 硬件保护，
  而那正是这个 App 全部安全性所依赖的东西。**绝对不要。**
- **手动把密码打到备忘录里再复制**：备忘录是明文的，等于没加密。

**如果你哪天改主意想买账号**：`docs/PAID_FEATURES.md` 里记录了
加回自动填充需要动的所有地方（含那个"IOS 18 passkey-aware 表单会黑屏"
的坑）。代码在 git 历史里，不用重写。

### 妥协 2：主密码强度无法被技术弥补

60 万次 PBKDF2 只能把攻击成本乘以 60 万。
如果主密码是 `password123`，攻击者几秒钟就能跑完字典。
**KDF 迭代次数保护的是"已经很强的密码"**，它救不了弱密码。

界面上强制的强度门槛（<60 bit 不让提交）就是为此。
推荐 **4 个随机中文/英文单词**。

### 妥协 3：没有实时多设备同步

v0.1 只有"加密备份 / 恢复"，没有 CloudKit 级别的记录级合并同步。
原因：正确实现同步需要处理冲突解决、墓碑记录、跨设备时钟偏移——
这是数量级的复杂度增长，而且**做错的同步会静默丢数据**。
"导出一份密文丢进 iCloud Drive"能覆盖 95% 的灾备需求。

### 妥协 4：不抓网站图标

列表用的是生成的字母图标，不是 favicon。
因为抓 favicon 需要向第三方服务器发请求，会实时暴露
"我在用哪些网站"。密码管理器最不该做的事就是主动往外发请求。

另外顺带一提：`monogramColorIndex` 用的是 Swift 的 `String.hashValue`，
它在**每次进程启动时重新随机化**。所以同一条目在不同次启动后颜色可能会变。
这是刻意接受的（要修需要一个稳定哈希，成本大于收益）。

## 四、你必须做的三件事

技术措施只能覆盖到这里，剩下三件事只能你做：

1. **主密码用 4 个随机单词，且只在这里用。**
   不要用你任何其他账号用过的密码。这条比其他所有措施加起来都重要。

2. **创建库之后立刻导出一次加密备份，存到手机之外的地方。**
   忘密码 = 数据永久丢失，这是设计而非缺陷。备份是唯一的保险。

3. **记住这个 App 没有自动填充，所以永远不要往你"不确定是不是官网"的页面上粘贴密码。**
   这是手动复制粘贴流程里唯一真正的风险点：
   钓鱼网站最爱骗的，就是"我现在要粘贴密码"这个动作。
   粘贴前扫一眼地址栏——这个习惯比任何技术措施都有效。

## 五、密码学参数一览

| 项目 | 取值 | 说明 |
|---|---|---|
| 对称加密 | AES-256-GCM | CryptoKit，AEAD，密文自带完整性标签 |
| 文件头完整性 | 整个头部作为 AAD | 改迭代次数/盐/库 ID → 解密失败 |
| 密钥派生 | PBKDF2-HMAC-SHA256，600,000 次 | 文件头记录迭代次数，将来可无损升级 Argon2id |
| 盐 | 32 字节 CSPRNG | 每库唯一；换密码时重新生成 |
| 子密钥分离 | HKDF-SHA256，info = `"vault-content-v1"` | 内容密钥 ≠ 主密钥 |
| 校验值 | HMAC-SHA256(masterKey', "pwvault.verifier.v1") | 仅用于区分"密码错"和"文件坏" |
| 随机源 | `SecRandomCopyBytes` | 失败直接崩溃，绝不退化成伪随机 |
| 密码生成 | 拒绝采样（无取模偏差） | 20 位全字符集 ≈ 130 bit |
| 常数时间比较 | `Data.constantTimeEquals` | 用于变更检测比较，避免时序泄露 |

**升级路径**：文件头有 `KDF_ALGO` 字段（当前 `1 = PBKDF2-SHA256`）。
将来若要迁移到 Argon2id，新增 `2 = Argon2id`，
按库的算法标识分流处理，老库不需要强制迁移。
