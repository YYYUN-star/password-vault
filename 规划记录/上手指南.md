# 零基础操作指南：把代码传到 GitHub 并在云端编译

这份指南假设**你完全不懂编程**。每一步都写清楚"点哪里、看到什么、正常应该是什么样"。

> **指南已根据你机器的实际情况改写过。**
> 我实测发现：你的网络**连不上 `github.com`**，但有两个域名是通的 ——
> 所以原本"装 GitHub Desktop 图形界面"的方案被换掉了（那个 226 MB 的安装包
> 按你当前网速要下 72 分钟）。现在走**命令行 + SSH 备用通道**，
> 不需要下载任何东西，因为你机器上的 Git 已经够用了。

## 最快的走法：双击一个文件就完事

打开文件夹 `D:\Deek\手机端\苹果密码管理App-失败版\tools`，**双击 `一键配置.bat`**。

它会自动按顺序做两件事，全程只要回答三个问题：

| 它问什么 | 你填什么 |
|---|---|
| `请输入你的 Bundle ID` | 你的名字拼音，比如 `com.zhangsan.passwordvault` |
| `确认修改吗？输入 y` | 输入 `y` 回车 |
| `请输入你注册 GitHub 时用的邮箱` | 你注册 GitHub 用的邮箱 |
| `请输入你的名字或昵称` | 比如 `zhangsan` |

**跑完最后会打印一段以 `ssh-ed25519` 开头的公钥**，把它整段复制下来，
然后跳到本文的「第 4 步：把公钥贴到 GitHub」。

> 窗口最后会停住并显示 `请按任意键继续`，所以你有时间慢慢复制。
>
> 如果双击后被 Windows 拦截（说文件来自 Internet 之类），点
> 「更多信息」→「仍要运行」。`一键配置.bat` 的正文是纯 ASCII，
> 所以不会出现中文乱码。

## 如果你想分开跑（或者双击没反应）

**方法一：右键运行（最直观）**

1. 进入 `tools\` 子目录，右键 `settings-bundleid.ps1` → **「使用 PowerShell 运行」**
2. 答完问题后，再右键 `config-github.ps1` → **「使用 PowerShell 运行」**

**方法二：终端里跑（右键菜单里找不到上面那项时用这个）**

1. 进入 `tools\` 子目录，右键 `settings-bundleid.ps1` → **「在终端中打开」**
   （没有这一项就用：在文件夹地址栏输入 `cmd` 回车）
2. 输入下面这行，回车：

   ```
   powershell -ExecutionPolicy Bypass -File .\settings-bundleid.ps1
   ```

3. 答完问题后，同样地跑第二个：

   ```
   powershell -ExecutionPolicy Bypass -File .\config-github.ps1
   ```

> `-ExecutionPolicy Bypass` 的意思是"这一次放过这个脚本"。
> 只是临时生效，不改你系统的任何设置。

## 为什么有一堆看起来重复的文件？（不用管，但解释一下）

| 文件 | 作用 |
|---|---|
| **`tools\一键配置.bat`** | 双击入口，按顺序调用下面两个脚本 |
| `tools\settings-bundleid.ps1` | 改 Bundle ID |
| `tools\config-github.ps1` | 配置走 SSH 443 端口的通道 |
| `tools\推送到GitHub.bat` | 双击执行 git push |
| **`_msgtable.ps1`** | 上面两个脚本的中文提示表，**不能删**，必须和它们放在同一目录 |

**为什么脚本在 `tools\` 子目录**：项目根目录只放 iOS 工程本身（这样 GitHub 上
看到的仓库是干净的）。辅助脚本是这台 Windows 电脑专用的，写进了 `.gitignore`，
不参与提交。

**为什么文件名是英文**：`.bat` 里引用中文文件名时，在 GBK 代码页下会变成乱码
（我实测踩过），所以统一用英文名。

## 先搞懂我们在做什么（1 分钟）

- **GitHub** = 一个网上的"代码仓库"，类似百度网盘，但专门存代码。
- **Git** = 把文件传上去的工具。**你机器上已经装好了**（Git 2.55）。
- **GitHub Actions** = GitHub 附带的"免费云端苹果电脑"。你每次上传代码，
  它就自动帮你**编译**一次，然后告诉你"成功"或"第几行有错"。

**为什么必须用它**：写 iPhone App 必须用苹果电脑（Mac）上的 Xcode 软件，
你用的是 Windows，装不了。所以借 GitHub 的免费 Mac 用。

**仓库要设为 Public（公开）**：公开仓库的 Mac 额度无限免费。

> 代码公开安全吗？**安全**。加密密钥是你在手机上输的主密码生成的，
> 从来不在代码里。公开代码 = 别人知道你的保险箱是什么牌子，但打不开它。

## 我实测出来的网络情况（决定了后面怎么走）

| 域名 | 状态 | 用途 |
|---|---|---|
| `github.com` | ❌ **连不上**（TCP 443 超时） | 网页、git 默认推送 |
| `desktop.githubusercontent.com` | ✅ 通 | 下载 GitHub Desktop（226 MB，太慢，放弃） |
| **`ssh.github.com:443`** | ✅ **通** | **GitHub 官方给受限网络准备的 git 备用通道** |
| `gitee.com` / `gitcode.com` | ✅ 通 | 国内代码托管（暂时用不到） |

**所以路线是：走 SSH 通道推代码。** 这也是 GitHub 官方支持的方案
（专门为"公司防火墙封了 22 端口"这类场景准备的）。

另外我发现一个坑：**Windows 自带的 SSH 太老**（9.5 版），
不支持 GitHub 现在用的密钥交换算法，会直接握手失败，报
`choose_kex: unsupported KEX method`。
**Git 2.55 自带的 SSH 是 10.3 版，完全可用。** 下面的脚本会自动选对的那个。

## 第 1 步：注册 GitHub 账号

1. 打开 https://github.com/signup
2. 依次填：邮箱 → 密码 → 用户名（英文，比如 `zhangsan2026`）

## 第 2 步：改 Bundle ID

**什么是 Bundle ID**：iPhone 上每个 App 都有一个全世界唯一的编号，
长得像把网址倒过来写，比如 `com.zhangsan.passwordvault`。
项目里现在写的是 `com.example`（意思是"示例"），必须改掉。

1. 打开文件夹 `D:\Deek\手机端\苹果密码管理App-失败版`
2. 找到 **`tools\settings-bundleid.ps1`**
3. **右键它** → 选 **「使用 PowerShell 运行」**
4. 如果弹出蓝色警告，点 **「更多信息」** → **「仍要运行」**
5. 输入你的名字拼音，例如 `com.zhangsan.passwordvault`，回车，再输入 `y` 回车

**正常应该看到**：最后一行是 `完成！没有残留的示例值。`

---

## 第 3 步：配置 SSH 连接（最关键的一步）

1. 在同一个文件夹，找到 **`tools\config-github.ps1`**
2. **右键** → **「使用 PowerShell 运行」**
3. 它会问你两个问题：
   - **邮箱**：填你注册 GitHub 用的那个邮箱
   - **名字**：填个昵称，比如 `zhangsan`
4. 然后它会自动做完剩下的事

**正常应该看到**（关键几行）：

```
[OK] git 已安装：C:\Program Files\Git\cmd\git.exe
[OK] ssh: C:\Program Files\Git\usr\bin\ssh.exe
     version: OpenSSH_10.3p1, ...
[OK] 已生成新密钥：C:\Users\你\.ssh\id_ed25519_github
[OK] 已写入配置文件：C:\Users\你\.ssh\config
[OK] git core.sshCommand set
[OK] known_hosts updated with 2 host key line(s)

=== 步骤 4：测试连接（最关键的一步）===
  git@ssh.github.com: Permission denied (publickey).
  看到 permission denied 或 successfully authenticated = 通道正常。
```

**看到 `Permission denied (publickey)` 就是成功了！** 这句话的意思不是"失败"，
而是"网络通了，但 GitHub 还不认识你这把钥匙"。下一步就是让它认识。

最后它会打印一段**公钥**，长这样：

```
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAI... 你的邮箱
```

**整段复制下来**（从 `ssh-ed25519` 开始，到邮箱结束，一行），下一步要用。

> **窗口一闪就没了 / 看不到公钥**：右键 `tools\config-github.ps1`
> → 「在终端中打开」，然后输入
> `powershell -ExecutionPolicy Bypass -File .\config-github.ps1` 回车。

## 第 4 步：把公钥贴到 GitHub

1. 浏览器打开 https://github.com/settings/keys
2. 点绿色按钮 **New SSH key**
3. **Title** 随便填，比如 `windows-pc`
4. **Key type** 保持 `Authentication Key`
5. **Key** 那一栏，把刚才复制的公钥**整段粘贴**进去
6. 点 **Add SSH key**

**这个页面能打开，说明你的浏览器到 github.com 是通的**，
只是命令行的连接被拦了。这在实践中很常见（浏览器可能走了代理，
或者网络对不同协议的处理不一样）。

验证一下（打开 cmd 输入）：

```
ssh -T git@github.com
```

**正常会回**：`Hi 你的用户名! You've successfully authenticated...`

2. 页面上方点 **Actions** 标签
3. 会看到一个叫 **build** 的任务

### 三种情况

**🟡 黄色转圈 = 正在编译**
正常。第一次要 3–5 分钟（下载 XcodeGen、生成工程、编译 3000 多行代码）。

**✅ 绿色对勾 = 编译成功**

点进去能看到日志，里面有 "Swift 总行数"、"entitlements 干净"。

**❌ 红色叉 = 编译失败**

2. 点左边栏的 **编译验证**

4. **从第一行 `error:` 开始往下复制 20–30 行**，贴给我

> 我拿到报错原文通常几分钟就能修好，你只要重新执行
> `git add -A` → `git commit -m "fix"` → `git push` 三条命令。

## 常见卡点

**Q: 右键没有「使用 PowerShell 运行」这个菜单项**
A: 右键 → 「在终端中打开」（或「在此处打开 PowerShell 窗口」），
然后输入 `powershell -ExecutionPolicy Bypass -File .\config-github.ps1` 回车。

**Q: 脚本里的中文显示成乱码**
A: 那是 PowerShell 窗口的字体/编码问题，**不影响功能**。
（脚本源码我特意写成了纯 ASCII，就是为了避免真乱码；窗口显示层的问题不影响它做的事。）
只要看到 `[OK]` 就说明成功了。

**Q: `git commit` 报错说 user.email 未配置**
A: 第 3 步的脚本没跑成功。重新跑一次 `tools\config-github.ps1`。

**Q: `git push` 卡住不动，很久没反应**
A: 按 `Ctrl+C` 中断，然后输入 `ssh -T git@github.com` 测试连接。
如果这个命令 25 秒内没反应，说明 SSH 通道也不通了 —— 告诉我。

**Q: 我想改 Bundle ID 了**
A: 再运行一次 `tools\settings-bundleid.ps1` 就行，它会自动覆盖旧值。

**Q: 我能把这套流程搬到另一台电脑吗**
A: 能。在新电脑上先跑 `tools\config-github.ps1`（它会生成新密钥），
把新公钥贴到 GitHub 就行。GitHub 允许一个账号有多个密钥。

**Q: `_msgtable.ps1` 这个文件是干什么的？能删吗？**
A: 不能删。`tools\config-github.ps1` 的所有中文提示都存在这个文件里
（为了绕开 PowerShell 的编码坑）。删了脚本会报找不到文件。
两个文件要放在同一个目录里。
